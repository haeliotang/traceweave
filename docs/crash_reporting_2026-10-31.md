# 崩溃上报的最小方案（缺口 10）

状态：**本地捕获已实现，上传未做**。

## 1. 已实现

- `CrashLog` 在 `MainActivity` 启动时安装默认未捕获异常处理器，把最后一次崩溃写到 `files/last_crash.txt`（上限 64 KB）；
- 审计页的“导出诊断”JSON 带 `last_crash`，其中 `summary` 是“异常类型 + 前 5 帧”，`raw` 是原始堆栈；设备上已用合成崩溃验证（[diagnostics_with_crash_20261031](../artifacts/agent_os/next_stage/diagnostics_with_crash_20261031.json)）；
- **不会自动上传**，只有用户主动导出时才离开设备。

## 2. 为什么不自动上报

| 风险 | 说明 |
|---|---|
| 隐私 | 堆栈里可能含任务标题、记忆片段等用户内容 |
| 合规 | 自动上传需要隐私政策与同意流程 |
| 基础设施 | 需要接收端、限流、去标识化 |

## 3. 若要加自动上报，最小可行路径

1. **用户显式同意**：设置页增加开关，默认关闭，写明上传内容与目的；
2. **裁剪**：只上传异常类型、堆栈的类名/行号、应用版本、Android 版本，不含任何字符串字段；
3. **批处理**：下次联网时上传，失败即丢弃，不做重试队列；
4. **可撤回**：上传前可预览将要发送的 JSON。

## 3.1 导出前先预览

“导出诊断”现在先弹一个确认框，列出**将要写入的全部字段**与崩溃摘要，用户点“选择位置”才会打开文件选择器。设备上验证：弹窗显示 `包含字段：app、version_name、version_code、android、device、tasks、memories、sync_runtime、recent_events、last_crash、note`，并附崩溃摘要；确认后导出的文件字段与预览一致。截图 ui/diagnostics_preview.png。

## 4. 验证

- 宿主测试覆盖 `CrashLog.format`（含空值与截断）；
- 设备端未刻意制造崩溃；如需验证，可在测试构建里加一个“立即崩溃”按钮，再检查 `last_crash.txt` 与导出诊断内容。
