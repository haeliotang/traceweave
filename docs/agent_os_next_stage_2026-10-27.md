# Agent OS 后续开发：验证、设计与未完成项

## 真机界面与感知

在独立验证应用中，以合成目标通过真实系统选择器保存 Markdown，应用读回后报告核验通过。继续创建日历草稿、单独确认后交给 Etar；按合成标题在本地日历精确查询，确认日程存在。返回 Agent OS 后显示结果未知；合成文件和日程均已核对并清理。记录见[界面与感知](../artifacts/agent_os/next_stage/real_ui_and_sensor_partial.json)。

光照显示观察到变化。单独的物理传感器测试在静置时收到加速度计和陀螺仪事件，形成 41 个窗口样本并输出 LowMotion。随后用户实际移动手机，界面显示状态变化；审核框显示从检测到运动回到低运动，观察已丢弃而未保存为记忆。该单次验证不证明普遍运动识别精度。没有采集或保存原始 IMU 序列，测试包及模型测试文件已清理。

## 有限多步模板

这不是任意步骤编排器：当前只允许规定顺序的文件与日历，不支持任意插件、循环或条件步骤。隔离应用的实际界面已创建模板、选择零条记忆、保存并读回文件，然后显示日历的独立确认；该次在交接前取消并清理文件，记录见[界面验收](../artifacts/agent_os/next_stage/workflow_ui_20261027.json)。0.6.3 生产候选随后完成了完整自动验收；该轮没有重新运行人工系统选择器。

## 本地模型评估

独立实验使用 [llama.cpp](https://github.com/ggml-org/llama.cpp) 固定提交 `d78f40d9d34d7a72ecdcd2e854f75ff86afc8ca3`，模型为 [Qwen2.5-0.5B-Instruct-GGUF Q4_0](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/blob/main/qwen2.5-0.5b-instruct-q4_0.gguf)，下载文件 SHA-256 与发布页一致。模型和工具临时放在设备 shell 专用测试目录，执行合成提示词，没有连接云端或使用个人记忆。该实验不是应用集成或生产部署。

一次测试的设备端工具报告载入 301.64 ms、生成 34.98 token/s；电脑端测得全程 3.67 秒，三次采样的最大进程 RSS 为 481920 KiB。数字只覆盖一次 CPU、四线程、512 token 上下文的测试，采样不保证捕获真正内存峰值。后续两条合成提示词中，严格 JSON 字面断言未通过：命令行输出包含代码围栏和结束标记；中文问题的输出也不满足所请求的三项。不能将这些结果作为通用质量或续航结论。

一般任务规划仍使用规则逻辑，原生模拟报告不作为实际模型结果返回。隔离 Android 测试壳通过真实模型加载、输出 UTF-8 校验、输入长度限制、启动前与运行中取消检查，见[实验收据](../artifacts/agent_os/next_stage/local_model_jni_probe.json)。0.6.5 增加单独的端侧模型文稿入口，不把模型输出当作动作授权；文件保存仍需用户审核并单独确认。

实验运行时可使用 `agent_os/scripts/build_experimental_model_runtime.py` 从固定提交的干净 llama.cpp 源码和本机 Android NDK 离线重新构建。脚本只产出隔离探针库和源码、产物摘要，不下载或打包模型，也不安装应用；构建前后会检查源码状态。构建成功不等于质量、安全或真机验收通过。 2026-10-28 重建产物在 Pixel 隔离包中通过加载、输入限制和取消验证。五条固定合成提示中三条通过精确检查，中文精确回复和计算的精确格式未通过；结果见[质量记录](../artifacts/agent_os/next_stage/local_model_quality_20261028.json)。这是一次小样本格式检查，既不证明计算错误，也不代表整体质量。

同日使用官方 [Qwen2.5-1.5B-Instruct Q4_0](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/blob/dd26da440ef0330c47919d1ecae0966d24022222/qwen2.5-1.5b-instruct-q4_0.gguf) 文件并校验其 SHA-256，在相同隔离探针上运行五条合成提示。该模型同样有三条通过严格检查，但通过的是英文精确回复、中文精确回复与计算精确格式；严格 JSON 字面检查和三行清单检查未通过。每条耗时约 2.3–4.3 秒，包含重新加载模型；间歇采样的最大 PSS 为 1,229,353 KiB，见[比较记录](../artifacts/agent_os/next_stage/local_model_15b_quality_20261028.json)。该采样不保证捕获峰值，五个样本不足以评估整体能力、可靠性、发热或耗电，也不能据此选定生产模型。测试包和设备上的模型副本已删除。

随后在同一隔离探针上复测 0.5B：五条提示中英文、JSON 和清单的严格检查通过，中文与计算的严格格式检查未通过；每条约 1.0–2.0 秒，间歇采样的最大 PSS 为 591,449 KiB，见[复测记录](../artifacts/agent_os/next_stage/local_model_05b_quality_retest_20261028.json)。两次测试均为单次小样本，且时间包含逐条重新载入；内存采样不能保证捕获峰值，因此这些数字只用于初步比较，不能作为生产性能或可靠性的结论。测试包及设备上的模型副本已删除。

进一步用 1.5B 模型在没有网络权限的隔离应用内生成合成 Markdown 文稿，确认文稿进入真实审核界面，未确认的文件写入被拒；随后由测试代码模拟确认，写入隔离文件并读回验证。测试没有使用个人记忆、真实系统文件选择器或正式应用，设备上的模型副本和隔离应用已删除，见[模型文稿实验记录](../artifacts/agent_os/next_stage/local_model_document_probe_20261028.json)。该实验尚不是正式模型接入，也不证明任意模型输出的质量、安全、长期稳定性或功耗。

0.6.5 候选使用固定提交的 llama.cpp 运行库并随包提供其 MIT 许可证；用户从系统文件选择器导入固定的 Qwen2.5-1.5B-Instruct Q4_0 模型，导入时核对大小与 SHA-256，生成前重新校验。取消、错误文件或读写失败不会用未完成文件替换已有模型。无网络权限的隔离应用已通过真实系统选择器导入公开模型、使用合成目标生成待审核文稿；模型资源等待时的界面取消也经验证，见[端侧应用验收](../artifacts/agent_os/next_stage/local_model_app_20261029.json)。合成测试中未选择个人记忆，未在正式应用运行生成或确认保存；正式应用已导入公开模型。此能力仅用于用户审核的文稿，不是通用规划器，质量、连续运行、发热、耗电和令牌生成期间的界面取消仍需进一步验证。

## 用户记忆跨设备同步：设计门槛

当前 Android 正式应用只有用户主动的加密档案导入/导出；现有 Rust 同步实验不等于正式应用的自动同步。两套隔离内存库的现有测试覆盖加密包往返、错误口令、元数据篡改、旧包、删除墓碑和时钟偏差下的旧记录拒绝；[测试结果](../artifacts/agent_os/next_stage/sync_existing_tests.json)不证明设备配对或跨设备恢复已实现。

Android 存储层新增档案逐条冲突审核接口：先解密并保留供本次审核的快照，每个冲突必须明确选择，提交事务内重新核对冲突集合及本机记录，变化时中止，删除标记继续优先。隔离真机合成档案验证了分别保留与替换、缺少选择、审核后编辑和审核后删除，见[测试记录](../artifacts/agent_os/next_stage/archive_individual_review_20261030.json)。0.6.8 已接入逐条审核界面；中文和英文界面分别通过系统选择器、两条不同选择、最终确认及保存结果的隔离验收，见[中文记录](../artifacts/agent_os/next_stage/archive_review_ui_20261030.json)和[英文记录](../artifacts/agent_os/next_stage/archive_review_ui_english_20261030.json)。审核期间解密内容保留在应用内存中。这不是自动同步或因果版本合并。

进一步使用同一 Pixel 上两套不同 UID 的隔离安装，以合成加密档案模拟离线编辑：两边编辑同一条记忆，测试代码审核并选择目标版本，来源端再次审核后收敛；另一条记忆的删除传播后，旧档案重放在两边均未使其复活。可复现脚本重新运行通过，见[隔离分叉记录](../artifacts/agent_os/next_stage/memory_offline_branches_20261030.json)。这是手动档案接口的合成测试，选择由测试代码完成，没有第二台手机、配对或自动同步，也不证明恶意设备防护和旧备份物理删除。

Rust 同步原型的导入现已将删除、记忆和任务放入同一数据库事务：合成故障注入验证，后续记忆写入或任务日志失败时，先前删除及写入会一起回滚。11 项同步测试、4 项存储测试和 82 项核心单元测试通过，见[记录](../artifacts/agent_os/next_stage/sync_atomic_import_20261028.json)。该修复不改变原型的最后写入胜出冲突策略，也没有接入 Android、设备配对或经过认证的传输。

同步原型现在在导入解析及解码前拒绝超过 10 MiB 的档案或字段，导出也检查序列化后的大小，避免产出无法通过相同限制导入或传输的档案。边界回归包括 JSON 转义导致的尺寸增长；15 项同步测试通过。这些限制仅适用于 Rust 原型，不意味着 Android 自动同步已实现。

在 macOS 本机回环实验中，旧 TCP 原型两端同时发送各 10 MiB 合成内容时会因互相等待而失败；修复后并行收发，并在写入前拒绝超过 10 MiB 的本地内容。相同边界和小数据交换测试通过，84 项核心单元测试、8 项因果合并测试及明文存储策略测试通过，见[传输测试记录](../artifacts/agent_os/next_stage/sync_large_exchange_20261028.json)。这只是实验传输的可靠性修复，未提供设备认证、重放防护或生产同步。

在启用任何同步前应完成以下契约：

1. 每设备独立身份；用户在两台设备上明确核对配对信息。配对和后续传输须使用经审查的协议及实现，拒绝未知设备、重放、替换和过期请求；现有 TCP 原型不能直接作为可信通道。
2. 用户持有可离线恢复的密钥材料，恢复过程和设备丢失、撤销、轮换、旧设备重入都必须有隔离演练。服务端只存密文，但仍可能看到元数据；不能把设备 Keystore 当成可迁移恢复密钥。
3. 使用可识别并发的因果版本；并发编辑保留候选并交由用户选择，不以墙钟自动覆盖。删除传播需防止旧档案或长期离线设备复活已删除记录；墓碑何时可清理必须由设备确认与恢复策略共同决定。
4. 每次同步边界清晰，失败、重复和中断可恢复；文件 URI 授权、外部动作授权、云 API Key 不随数据复制。先完成两独立安装身份的断网、冲突、删除、恢复和拒绝测试，再考虑选择性启用自动同步。

Android 端新增未接入用户流程的设备身份基础：显式创建 Android Keystore P-256 签名密钥，读取和签名不会在密钥缺失时自动创建新身份；公开密钥可计算指纹，私钥不提供导出接口。Pixel 上两个独立安装 UID 的合成测试验证了签名、篡改挑战拒绝、强制停止后的稳定性、不同 UID 密钥不同以及私钥编码不可获取，见[测试记录](../artifacts/agent_os/next_stage/device_identity_20261030.json)。这没有验证第二台物理设备、设备重启、硬件证明或密钥丢失恢复；正式应用尚未调用或创建该身份。

当前 rust-libp2p 实验持有软件身份密钥，尚不能直接使用 Android Keystore 的不可导出私钥。若采用上述身份，必须先设计和验证它与每次传输身份、用户确认、撤销及防重放的绑定，不能把单次挑战签名视为配对完成；具体实现还需安全审查。Android Keystore 的密钥属性见[官方文档](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec)。

为探索绑定，设备身份可对有域分隔、带长度的发送方与接收方标识及 32 字节挑战签名；Pixel 隔离测试验证方向调换、挑战修改、跨用途复用及歧义编码被拒，见[测试记录](../artifacts/agent_os/next_stage/device_transport_binding_20261030.json)。本次标识为合成字节，编码不校验 PeerId，也不自动绑定已认证会话或防重放；调用方必须取得实际握手身份并验证挑战有效性。未接入正式应用、真实连接或用户配对，不得据此启用敏感记忆同步。

进一步的[隔离真机实验](../artifacts/agent_os/next_stage/device_noise_binding_20261030.json)在 Mac 与 Pixel 经 USB 转发建立 Noise 连接后，用实际认证的双方 PeerId 验证 Pixel Keystore 对合成挑战的签名，并由宿主测试进程在内存中拒绝同一次运行的重复提交。挑战通过测试脚本在连接前提供，未绑定 Noise 会话或握手记录；传输密钥是公开测试夹具，防重放不跨进程，也没有用户配对或正式应用接入。该结果不能作为生产同步安全性的证明。实验代码位于 [libp2p_live_binding](../agent_os/tests/libp2p_live_binding/)。

后续[会话挑战实验](../artifacts/agent_os/next_stage/device_noise_challenge_20261030.json)在 Noise 连接建立后由接收端测试监督进程生成随机挑战，经该连接发送，手机返回 Keystore 签名；接收端按实际 PeerId、挑战和测试密钥验签，并在同一进程中拒绝重复提交。测试监督进程通过 ADB 将收到的挑战交给手机隔离签名界面，因此尚不是应用内直连；也未绑定握手记录、验证多连接下的会话关联、实现过期或跨重启防重放。测试密钥为公开夹具，验签公钥随测试证明取得，没有用户配对，不能证明真实信任。

实验性 [causal_memory.rs](../agent_os/core/src/causal_memory.rs) 对同一记忆 ID 的版本进行纯函数合并：因果较旧的版本被排除；并发编辑作为多个候选保留；用户选择后合并所有已审核候选的时钟并递增本机计数；永久墓碑优先于并发编辑和旧版本。新增的[六项测试](../artifacts/agent_os/next_stage/causal_merge_tests.json)覆盖两份隔离状态、并发选择、重放、删除、输入限制与相同时钟不同内容的拒绝。此规则以不复活删除为先，会丢弃与删除并发的编辑；如需保留此类编辑，必须另行设计不违反删除意图的用户恢复流程。

该原型没有接入 Android 规范记忆库、持久化、配对、网络、密钥恢复或外部动作；调用方还必须在同一事务中验证被用户审核的候选集合仍未变化。其测试不证明安全同步。上述设计与准入条件也不是已实现的配对或同步协议。密码学、重放防护和冲突合并必须接受独立审查后才能使用真实敏感数据。

后续边界测试发现，两个各自合法的并发版本合并后可能涉及超过 32 台设备；冲突选择现在会拒绝生成超过该上限的时钟，而不会产生后续合并无法接受的结果。恰好 32 台且由已有设备选择仍被允许。这项修复只覆盖实验性合并规则。

另增加只在 Rust 测试配置编译的 SQLite 合成夹具，用两个独立数据库检查重开后保留冲突、用户选择后收敛、删除后拒绝旧选择、另一连接提交删除与选择竞争，以及非法输入回滚。夹具使用临时明文数据库、仅含合成内容，并在测试结束删除；它不是正式持久化实现，不得用于用户数据。测试没有实现设备身份、加密存储、传输认证或恢复流程。

为避免自行实现完整冲突合并，2026-10-29 评估了 [Automerge 主项目](https://github.com/automerge/automerge)和其 [Java/Android 绑定](https://github.com/automerge/automerge-java)。当日 GitHub API 分别显示约 6,694 和 49 个 star；主项目较成熟，但 Android 绑定的社区规模较小。官方 [0.0.9 发布](https://github.com/automerge/automerge-java/releases/tag/v0.0.9)提供 Java 包和 Android 原生 AAR，另声明 SLF4J 接口依赖；Android arm64 原生库约 6.4 MB，本次检查其 ELF 加载段对齐为 16 KiB，不能据此推断所有设备兼容。

在没有网络权限的 Pixel 隔离应用及电脑端，以合成内容验证并发编辑的两个候选、保存后重载、选择后的收敛和旧版本重放；隔离应用已卸载，见[实验记录](../artifacts/agent_os/next_stage/automerge_android_20261029.json)。直接删除字段与并发编辑合并时，编辑仍可见；旧内容也可通过历史版本访问。单独设置墓碑的合成实验中，墓碑在正常客户端的离线编辑与旧版本重放后保留，但这没有验证恶意或损坏客户端，也没有消除历史内容。因此不能直接用默认删除行为满足本项目的删除优先与用户删除预期，也不能把 CRDT 历史视为已经物理擦除。若继续采用，应把永久墓碑、对旧设备和旧备份的处理、历史保留及清除策略作为独立设计，并验证用户可见的冲突选择。Automerge 只作为合并候选，不提供本项目所需的设备认证、端到端加密和密钥恢复；此次没有将依赖加入正式应用，也未使用真实记忆。发布包摘要是本次下载文件的固定校验值，不构成独立签名或供应链审计。

传输层候选可优先评估 [rust-libp2p](https://github.com/libp2p/rust-libp2p)：2026-10-29 GitHub API 显示约 5,630 个 star，仓库标记 MIT；其 [Noise 协议规范](https://github.com/libp2p/specs/blob/master/noise/README.md)将传输握手密钥绑定到节点身份。它不替应用完成用户核对设备、撤销、备份恢复或离线冲突语义，亦不能单独证明服务端密文存储。相比之下，[libsignal](https://github.com/signalapp/libsignal) 的 Android 发布配置声明 AGPL-3.0，采用前需评估与本项目 Apache-2.0 分发目标相关的义务；[Snow](https://github.com/mcginty/snow) 作者明确说明尚未接受正式审计。
