# Substrate Protocol Specification v1.0 (Historical Design)
**Status**: Experimental; TCP/UDS transport is disabled in the Android Binder-only MVP
**Revision**: 1.0.0
**Target Architecture**: Historical cross-platform proposal; only Android Binder is currently supported

> Current implementation scope is defined by [the Android Binder-only MVP decision](../agent_os_android_binder_mvp.md). This document's TCP/UDS envelope and cross-device behavior are design material, not a running service contract.

---

## 1. Overview & Architectural Principles

The **Substrate Protocol** defines a vendor-neutral, non-custodial execution and permission substrate for personal AI agents. It establishes an open boundary where multiple autonomous agents—regardless of whether they are developed by different vendors, open-source communities, or running locally—interact with personal data, capabilities, and cross-device tasks under unified user governance.

### Core Tenets

1. **Separation of Agency and Ownership**: Agents are ephemeral and replaceable. Identity, long-term memory, capabilities, and audit records belong strictly to the user substrate.
2. **Just-In-Time (JIT) Least Privilege**: Capabilities are granted on-demand with strict temporal bounds (default 5 minutes TTL) and scoped access limits. No permanent or blanket permissions are ever granted.
3. **Decoupled Cryptographic Vault**: Data encryption keys (DEK) are enveloped by a user master key (UMK) derived via PBKDF2-HMAC-SHA256 (600,000 rounds). Data retention is independent of any single APK or application lifecycle.
4. **Append-Only Tamper-Evident Auditability**: Every authorization grant, capability invocation, revocation, and denial creates an immutable audit trail tagged with the originating agent identity.
5. **User-Mediated Portability**: The Android MVP supports encrypted archive export/import initiated by the user. Automatic cross-device synchronization is not implemented.

## 2. Transport Layer Bindings

The current MVP supports one transport:

### 2.1 Android Local IPC: AIDL Binder
- **Service Name**: `org.traceform.agentos.SubstrateService`
- **Action Intent**: `org.traceform.agentos.action.BIND_SUBSTRATE`
- **Authentication**: Binder caller UID, package ownership, and the installed APK signing certificate SHA-256; capability use still requires explicit user approval
- **Interface Definition**: `org.traceform.agentos.IAgentSubstrate`

```aidl
package org.traceform.agentos;

interface IAgentSubstrate {
    String registerAgent(String agentPackage, String legacyAgentPublicKeyHash, String manifestJson);
    String listCapabilities(String sessionToken, String taskId);
    boolean requestCapability(String sessionToken, String taskId, String capability, String scope);
    String invokeCapability(String sessionToken, String taskId, String capability, String scope);
    boolean revokeCapability(String sessionToken, String taskId, String capability, String scope);
    String queryAuditLog(String sessionToken, String taskId, int limit);
    String ping(String sessionToken);
}
```

The Binder host derives an Agent identity from the sole package associated with the caller UID and that package's current APK signer SHA-256. It rechecks UID, package ownership, and signer on each call. The `legacyAgentPublicKeyHash` argument is ignored and must not be used as proof of key ownership.

### 2.2 Reserved: Cross-Platform Stream over TCP / UDS

This transport is not implemented or available in the MVP. The Rust `agentosd` binary exits disabled, and the Python client fails closed. Do not treat the following historical port and socket values as active endpoints.

- **TCP Default Port**: `19898` (loopback / local network)
- **Unix Domain Socket (UDS)**: `/tmp/agentosd.sock` or `/data/local/tmp/agentosd.sock`
- **Framing**: UTF-8 encoded JSON strings delimited by newline (`\n`, `0x0A`).

## 3. Wire Protocol & Envelope Schema

Every TCP / UDS interaction follows a synchronous or asynchronous request-response pattern.

### 3.1 Request Envelope
```json
{
  "id": "req-uuid-or-counter",
  "action": "action.name",
  "agent_id": "optional.string.identifying.agent",
  "session_token": "optional.session.token",
  "timestamp_ms": 1792761000000,
  "payload": {}
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | String | Yes | Unique correlation identifier generated by the client. |
| `action` | String | Yes | Action method to execute (e.g., `agent.register`, `capability.invoke`). |
| `agent_id` | String | No | Declared agent identity for auditing and credential binding. |
| `session_token` | String | Conditional | Active authentication token returned by `agent.register`. Required for all protected actions. |
| `timestamp_ms` | Integer | No | Client Unix timestamp in milliseconds. |
| `payload` | Object | Yes | Action-specific parameters dictionary. |

### 3.2 Response Envelope
```json
{
  "id": "req-uuid-or-counter",
  "status": "ok",
  "timestamp_ms": 1792761000100,
  "data": {},
  "error": null
}
```

| Field | Type | Description |
|---|---|---|
| `id` | String | Matches the correlation `id` from the request. |
| `status` | String | Status code: `"ok"` on success, `"error"` on failure. |
| `timestamp_ms` | Integer | Server Unix timestamp in milliseconds. |
| `data` | Object | Action-specific return payload (null if status is `"error"`). |
| `error` | String / Null | Descriptive error message when status is `"error"` (null on success). |

### 4.2 Agent Identity & Session Management

#### `agent.register`
Registers an external agent identity, validates manifest declarations, and issues a 24-hour session token.
- **Payload**:
  ```json
  {
    "agent_id": "org.agent.researcher",
    "public_key": "optional-base64-or-hex-public-key",
    "manifest": {
      "manifest_version": 1,
      "agent": {
        "id": "org.agent.researcher",
        "name": "Research Agent",
        "version": "1.0.0",
        "description": "Performs deep document synthesis"
      },
      "capabilities_requested": [
        {"capability": "demo.note.read", "scope": "synthetic.welcome", "reason": "Inspect task summary"}
      ]
    }
  }
  ```
- **Response Data**:
  ```json
  {
    "session_token": "sub-session-0a1b2c3d4e5f...",
    "agent_id": "org.agent.researcher",
    "registered_at": 1792761000000,
    "expires_at": 1792847400000
  }
  ```

#### `agent.verify`
Checks the validity, expiration, and identity of an active session token.
- **Payload**:
  ```json
  {
    "session_token": "sub-session-0a1b2c3d4e5f..."
  }
  ```
- **Response Data**:
  ```json
  {
    "valid": true,
    "agent_id": "org.agent.researcher",
    "expires_at": 1792847400000
  }
  ```

#### `agent.list`
Lists all currently registered agents and active session counts (administrator/system access).
- **Response Data**:
  ```json
  {
    "agents": [
      {
        "agent_id": "org.agent.researcher",
        "registered_at": 1792761000000,
        "manifest": { ... }
      }
    ],
    "active_sessions": 1
  }
  ```

### 4.3 Capability Broker & JIT Permission Model

Capabilities represent guarded resources: filesystem reads, device sensors, remote communication, or UI interactions.

#### Capability Lifecycle State Machine
```
[Unrequested] ──(capability.request)──> [Pending User Approval]
                                                │
                 ┌──────────────────────────────┴──────────────────────────────┐
                 ▼                                                             ▼
           [User Approved]                                               [User Denied]
                 │                                                             │
                 ▼                                                             ▼
             [Granted] ──(5 min TTL)──> [Expired]                         [Terminated]
                 │
                 ├──(capability.invoke)──> [Audited Execution]
                 └──(capability.revoke)──> [Revoked]
```

#### `capability.list`
Enumerates capabilities declared in the broker and identifies which are currently granted for a task.
- **Payload**: `{"task_id": "task-uuid"}`
- **Response Data**:
  ```json
  {
    "capabilities": ["demo.note.read", "demo.status.read", "system.notify"],
    "active_grants": [
      {
        "agent_id": "org.agent.researcher",
        "task_id": "task-uuid",
        "capability": "demo.note.read",
        "scope": "synthetic.welcome",
        "expires_in_secs": 284
      }
    ]
  }
  ```

#### `capability.request`
Requests a short-lived JIT grant. Triggers user consent via floating capsule or system dialog if not previously authorized.
- **Payload**:
  ```json
  {
    "task_id": "task-uuid",
    "capability": "demo.note.read",
    "scope": "synthetic.welcome"
  }
  ```
- **Response Data**:
  ```json
  {
    "granted": true,
    "capability": "demo.note.read",
    "scope": "synthetic.welcome",
    "agent_id": "org.agent.researcher",
    "expires_at": 1792761350000
  }
  ```

#### `capability.invoke`
Executes an authorized capability. Fails immediately if grant is absent, expired, or agent identity does not match.
- **Payload**:
  ```json
  {
    "task_id": "task-uuid",
    "capability": "demo.note.read",
    "scope": "synthetic.welcome"
  }
  ```
- **Response Data**:
  ```json
  {
    "result": "Note content retrieved securely under grant.",
    "capability": "demo.note.read",
    "scope": "synthetic.welcome",
    "agent_id": "org.agent.researcher"
  }
  ```

#### `capability.revoke`
Explicitly revokes an active grant before expiration.
- **Payload**:
  ```json
  {
    "task_id": "task-uuid",
    "capability": "demo.note.read",
    "scope": "synthetic.welcome"
  }
  ```
- **Response Data**:
  ```json
  {
    "revoked": true,
    "capability": "demo.note.read",
    "scope": "synthetic.welcome"
  }
  ```

### 4.4 Cryptographic Vault Management

#### `vault.init`
Initializes the cryptographic vault using a user master passphrase, deriving UMK and wrapping the newly generated DEK.
- **Payload**: `{"passphrase": "user-secure-passphrase"}`
- **Response Data**: `{"initialized": true, "unlocked": true}`

#### `vault.status`
Queries whether the vault is unlocked in the current daemon process.
- **Response Data**: `{"unlocked": true}`

#### `vault.seal`
Encrypts plaintext data with the active DEK using AES-256-GCM.
- **Payload**: `{"plaintext": "sensitive data payload"}`
- **Response Data**: `{"sealed": "base64-sealed-envelope"}`

#### `vault.unseal`
Decrypts an encrypted payload with the active DEK.
- **Payload**: `{"sealed": "base64-sealed-envelope"}`
- **Response Data**: `{"plaintext": "sensitive data payload"}`

## 5. Security & Invariant Guarantees

1. **Identity Tagging**: Every grant and capability invocation records the exact `agent_id` in audit storage.
2. **Token Secrecy & Expiration**: Session tokens expire after 24 hours. A revoked session token immediately invalidates further capability requests.
3. **No Cross-Agent Contamination**: Agent A cannot invoke capabilities granted to Agent B. Every invocation verifies `session_token -> agent_id == grant.agent_id`.
4. **Offline Resilience**: The Substrate operates 100% on localhost (`127.0.0.1` / UDS / Binder) without cloud dependencies.
5. **Clean Logs Policy**: All protocol messages, error outputs, and system logs must adhere strictly to plain text with zero emoji decorations.
