# 同步入口与自动同步开关（F4 前置设计）

状态：**设计稿**。当前正式应用没有同步界面；F4 的"自动同步开关"必须先有可用的手动同步入口，否则只是假开关。

## 1. 现状

- 传输：`agent_os/sync`（libp2p/Noise），已完成两套隔离安装的端到端交换、冲突收敛与删除传播。
- 配对：正式应用有配对对话框与 `pairings` 表（device_id、fingerprint、peer_id、status）。
- 缺口：
  1. 配对记录只存 `peer_id` 字符串，没有存对端的**传输公钥**，而绑定验签需要它；
  2. 同步种子没有持久化；测试里用固定合成种子；
  3. 正式 APK 没有打包 `libtraceform_sync.so`，也没有 JNI 包装类；
  4. 没有"同步现在"入口与结果落地。

## 2. 需要补的四件事

### 2.1 传输身份持久化

- 首次使用时生成 32 字节种子，存 `SharedPreferences`（受应用沙箱保护），派生 Ed25519 PeerId 与公钥。
- 种子只在本机使用；导出/导入档案**不携带**种子（避免复制身份）。
- 正式应用启动时若检测到配对记录但种子缺失，标记"身份缺失"，要求重新配对。

### 2.2 配对记录扩展

- `pairings` 增加 `peer_public_key` 列（schema 10），配对时由对端提供并展示指纹供核对。
- 现有记录升级时置空；空值的配对视为"需重新配对"，不允许同步。

### 2.3 同步入口

- 设置页新增一行：`已配对设备：N` + `同步现在`。
- 点击后：
  1. 取活动配对（恰好一个时）；多个时让用户选择；
  2. 用 `peer_id` 与服务端地址（本版仅回环/局域网）发起一次交换；
  3. 收到记录后按 `mergeSyncRecords` 合并，展示"新增/冲突/删除"计数；
  4. 失败时展示原因，不自动重试；用户可再次点击。
- 结果写入审计事件，不写记忆内容到日志。

### 2.4 自动同步开关（F4 本体）

- 在手动同步入口通过验收后再加，默认关闭。
- 开启前要求：至少一个活动配对、用户再次确认、说明仅在前台/充电/局域网内的受限条件。
- 关闭立即停止调度；任何撤销配对会同时关闭该设备的自动同步。
- 第一版不做后台常驻：只在应用前台且用户允许时尝试。

## 3. 测试计划（两套隔离安装）

1. 安装 A/B，互相配对（现有配对对话框），各自生成种子并交换公钥。
2. A 点"同步现在"→ 进入监听；B 点"同步现在"→ 拨入；双方计数一致。
3. 冲突：两边改同一条记忆 → 交换 → 双方各 2 个候选 → A 选择 → 再同步 → 单版本。
4. 删除：A 删除 → 同步 → B 消失且不复活。
5. 撤销：A 撤销 B → B 再同步被拒；A 的自动同步开关自动关闭。

## 4. 明确不做

- 不做后台常驻同步、不做服务端中继（第一版）、不做跨账号。
- 不把同步当作授权：文件 URI、能力授予、云 Key 不随记录复制。
