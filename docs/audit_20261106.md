## 二、安全与密码学

### S1 ✅🔴 `ensureAnchors` 让锚定可被重置
`AgentStore.auditIntegrity()` 先读 anchors，再调用 `ensureAnchors(rows)`，后者为**缺失的每个索引重新计算 MAC** 并写回。
攻击路径：改写审计行 → 重算 SHA-256（不需要密钥）→ 删除 anchor 行（或整表）→ 打开审计页 → MAC 被重新生成 → 显示绿色。
`AnchorMac` 的注释「hand-edited database cannot produce new anchors without that key」因此不成立。
修复：在 DB 之外（Keystore 保护的首选项）保存「已锚定的最高索引」，拒绝为小于等于它的索引补锚；缺失锚点视为篡改；只允许带版本标记的一次性迁移回填。测试：删 anchor 行/整表后必须失败。

### S2 ✅🔴 同步身份没有真正的设备密钥绑定
`SyncTransport.seed()` 把 32 字节 Ed25519 种子明文存进 `agent_os_prefs`（`sync_seed`）。`DeviceIdentity` 的 P-256 签名只在测试 Activity 里使用；生产传输用同一把可导出的 Ed25519 key。
后果：复制 `sync_seed` 即可向仍保留配对的设备冒充本机；撤销只是本地记录。
修复：用 Keystore P-256 对绑定 transcript 签名并在对端用配对记录中的指纹验证；或用 Keystore 包裹 seed。

### S3 ✅🟠 配对码从未被用户校验
`SyncPanel` 计算完 6 位码后调用 `SyncPairing.confirm(..., code, code)`——**拿自己和自己比**。`confirm` 只比较两个入参，用户没有输入对端码的机会；按指纹路径的码完全由两个公开指纹导出。
修复：要求用户输入对端显示的码并做常量时间比较；SAS 绑定双方传输公钥与新鲜随机 nonce。

### S4 ✅🟠 配对码写进 logcat
`SyncPanel` 用 `Log.i` 记录含 sas/fingerprint 的 payload 与 session；Rust 拨号端 nonce 是固定常量 `[7u8;32]`，`pairing_session.rs` 的 nonce 是确定性序列。
修复：删除这些日志；双方用随机 nonce 并纳入 transcript。

### S5 ✅🟠 无障碍服务读取全窗口文本且写日志、无密码字段过滤
`accessibility_service_config.xml` 为 `typeAllMask` + `canRetrieveWindowContent` + `canTakeScreenshot`，无 `packageNames` 限制；`AgentAccessibilityService:103` 遍历所有窗口取文本；`VisionAgentManager:94` 用 `Log.d` 打印每个节点文本；全文件**无 `isPassword` / `FLAG_SECURE` 判断**。
修复：包白名单、过滤密码与安全窗口、禁止打印节点文本、必要时关闭截图能力。

### S6 ○🟠 脱敏两条路径规则不一致
Java 版 `ContextRedactor` 覆盖 password/token/secret；Rust 版 `redactor.rs` 只有 `sk-` / `Bearer` / `api_key`。生产环境 native 可用时走 Rust → `password: xxx`、`token=xxx` 会原样进入云端请求。
修复：单一规则源，用同一语料做 Java/Rust 交叉测试。

### S7 ○🟡 其他
- 诊断导出的 `last_crash.raw` 未清洗，而同一 JSON 的 `note` 声称不含任务文本；
- 档案可省略 `auditHead` 绕过校验（`ArchiveAudit.matches` 对空 head 返回 true）；导出按 `occurred_at` 排序而链头按 `rowid` 取；
- 口令以 `String` 形式存在堆中（`getText().toString()`），导出期间还常驻 Activity 字段；
- `appendAudit` 的「读最后哈希再插入」非原子，多实例并发会分叉；
- 审计 TSV 导出未转义制表符，存在列注入。

已验证安全做得好的点：档案 AEAD 参数（PBKDF2 600k、AAD 覆盖头、参数固定校验、清零）、HTTPS 强制 + 关重定向 + 响应上限、Python edge 档案的 TOCTOU 二次认证与路径穿越检查、供应链（固定 SHA、临时签名身份、Cargo.lock 无 git 依赖）、Substrate 会话与 Broker 的 UID/包名/签名绑定。

## 六、未知的未知（本次审计的主要产出）

1. **锚定可以被「自愈」重置**——文档只写了「尾部截断会作为更短的合法链通过」，没人把 `ensureAnchors` 描述为「对任何剩余行重新签名」。
2. **正常操作会制造假篡改**——测试只验证哈希链数学（编辑/截断），从不在「删除任务」「导入档案」后跑 `auditIntegrity`。
3. **导入的审计事件被当作真实历史**——档案 head 只保证「档案内自洽」，作者可自算；没有 imported 标记，朋友给的档案能伪造 `capability_granted`。
4. **同步的 Keystore 绑定只存在于注释和测试里**——生产通道用可导出的 Ed25519 种子，P-256 签名从未接线。
5. **配对码从未被用户校验**（`confirm(code, code)`），且随 logcat 泄漏。
6. **无障碍文本进 logcat 且无密码过滤**——文档把它标为「实验」，掩盖了具体泄漏与截图能力。
7. **设备 harness 的 PASS 判定太弱**（logcat 子串），action 名写错也可能绿。
8. **墙钟被当作向量时钟**（`clock.put(actor, System.currentTimeMillis())`）：时间回拨或同毫秒两次编辑会让合并判断错误。
9. **双密钥回退把「解不开」变成「不存在」**：vault 失败静默回退 Keystore，导出时 `continue`，用户只看到记忆消失。
10. **诊断导出的 note 是常量承诺**，而 raw 崩溃原文未清洗。
11. **迁移链七步（v7–v13）从未被执行过**。
12. **单设备假设**：SQLite/Keystore/JobScheduler/悬浮窗/音频只在 Pixel 6a 上验证。

## 八、修复路线图

**P0（数据与信任，优先）**

1. `deleteTask` / 导入不再删除审计行：改为追加 `task_deleted` 事件；导入审计用本地链重新链接；加「删除后 `auditIntegrity.ok`」设备用例。
2. `ensureAnchors` 收紧：记录最高已锚定索引（存 Keystore 保护的首选项），不再为历史索引补签；缺失锚点视为篡改。
3. 记忆编辑/删除/导入补 `memory_versions`；`exportSyncRecords` 遇到无版本行写审计事件而不是静默跳过。
4. 迁移链补测试（按版本生成夹具），设备断言改用 `DATABASE_VERSION` 常量。
5. `SubstrateService` 加 signature 级权限或包签名白名单。

**P1（真实设备会坏）**

6. 旋转丢口令 → 导出必失败（改 `registerForActivityResult` + 保存状态/重弹口令）。
7. 换机迁移 `dataExtractionRules` + 不可解密时的「重建本地库」入口。
8. 胶囊：`startForeground` 或去掉 FGS 声明；修隐藏后旋转重现；删掉死掉的 JIT 面板。
9. 每秒全量重建 → 状态签名变化才重建，且读库移出主线程。
10. edge-to-edge insets（systemBars/displayCutout/ime）。

**P2（发布可信度与长期性）**

11. 修 v0.1.0 正文占位符；四个版本补「开发密钥侧载」；README/发布流程/SECURITY 对齐现状；补安装段落与权限表。

13. 审计裁剪策略 + 导出流式化；配对码日志删除、SAS 真正校验、nonce 随机化。
