# 自动后台同步设计草案（2026-10-31）

状态：**设计草案，未实现**。当前应用只有前台手动同步与“应用打开时自动同步一次”的开关（默认关闭）。

## 1. 目标与非目标

目标：在两个已配对设备之间，让用户在不开着应用的情况下也能在合理延迟内收敛数据。

非目标：实时同步、后台常驻连接、云端中转、跨账号同步。

## 2. 约束

| 约束 | 影响 |
|---|---|
| Android 后台执行限制（Doze、App Standby、后台启动限制） | 不能常驻 socket；只能用 WorkManager 周期任务或前台服务 |
| 局域网多播在部分设备/系统版本受限 | mDNS 只能作为发现手段，需保留地址直连回退 |
| 电量与热 | 每次同步会加载模型（若触发端侧生成）；同步本身应避免唤醒模型 |
| 数据安全 | 配对与能力授权是显式动作，自动同步不得扩大授权范围 |
| 冲突语义 | 向量时钟 + 墓碑优先；自动同步必须复用同一套合并逻辑 |

## 3. 方案

**触发**：WorkManager `PeriodicWorkRequest`（最小 15 分钟，默认 1 小时），约束为“有网络 + 设备未省电”，并加 `setBackoffCriteria` 指数退避。用户可在设置里选择关闭/15 分钟/1 小时/仅充电时。

**执行**：Worker 启动后
1. 读取配对列表与上次游标（新增 `sync_cursor` 表：peer_id、last_synced_at、last_event_id）；
2. 对每个活跃配对尝试发现（mDNS，短超时 ≤5 s），失败则回退到已保存地址；
3. 建立 Noise 会话（复用现有 `serve_with`/`dial` 路径），交换增量（按向量时钟裁剪）；
4. 合并落库，写入审计事件 `sync_auto_completed`；
5. 全程 ≤60 s，超时则记录 `sync_auto_timeout` 并结束。

**不做什么**：不在 Worker 里加载模型、不自动执行任务、不自动批准能力。

## 4. 数据与审计

- 每次自动同步写一条审计事件（开始/结束/失败原因），可在审计页查看与导出；
- 不新增遥测；失败原因只留在本机。

## 5. 需要新增的代码

| 模块 | 内容 |
|---|---|
| `AutoSyncWorker` | WorkManager Worker，串行执行，持有 Mutex 防止与手动同步并发 |
| `SyncScheduler` | 按用户设置调度周期任务；开机与应用升级后重排 |
| `AgentStore` | `sync_cursor` 表与查询；迁移到 schema 10 |
| `SyncPanel` | 频率选择、上次自动同步时间、失败原因展示 |
| 测试 | 宿主测试覆盖调度参数与游标计算；设备测试覆盖“关闭时不触发” |

## 6. 风险与验证

| 风险 | 缓解 | 验证方式 |
|---|---|---|
| 后台被系统杀死 | 只做小步增量，靠下次周期补齐 | 断网/省电模式下观察是否退避 |
| 电量回退 | 默认关闭，充电时可更频繁 | 与 A2 功耗测量同法对比开关前后 |
| 与手动同步并发 | 单例 Mutex + 审计事件去重 | 同时点击“同步现在”与周期触发 |
| 冲突静默覆盖 | 复用墓碑优先与冲突候选，自动同步不自动选边 | 构造双端冲突用例 |

## 7. 分期

1. 数据层：`sync_cursor` + 增量查询 + 宿主测试；
2. 调度层：Worker 与开关，默认关闭；
3. 观察层：审计事件与设置页展示；
4. 评估：与功耗测量一起给出开关前后的差异，再决定是否默认开启。
