本文件把仍需操作人或外部条件的里程碑写成可照做的步骤，避免每次重新摸索界面。所有涉及真实数据的步骤都标了"需要用户当场授权"。

## A2 / D1 功耗与热测量（需要拔线 + 受控环境）

- 前提：电量 40%–90%，设备拔掉 USB（脚本会拒绝充电状态），静置 5 分钟，固定亮度、勿扰。
- 步骤：`python3 agent_os/scripts/measure_power_android.py --serial <serial> --baseline-minutes 5 --workload-minutes 10 --output artifacts/agent_os/next_stage/power_<date>.json`
  - 模型负载（D1）需先把 1.5B 模型放进探针包，并加 `--package <probe package>`。
- 产出：基线/负载的 %/小时、温度差、`batterystats` 片段；限制见[协议](power_measurement_protocol.md)。
- 若要功率计级结论：需要外接功率计与恒温环境，当前标记"受阻（外部计量设备）"。

## B3 真实分享发送（需要操作人选择接收应用）

1. 隔离包或正式包内准备一份合成文稿（例如 D4 生成的 Markdown）。
2. 走分享草稿流程，系统分享选择器出现后**选择一个真实接收应用**（如 Notebook）。
3. 在接收应用里核对内容与摘要，确认收到后删除接收端内容。
4. 记录：接收应用名、内容摘要、是否出现"结果未知"、是否自动重放（应为否）。

## B4 / B5 Traceweave 正式历史（需要用户当场授权）

当前状态：正式应用设置里的 `Enable Traceweave Provider` 默认关闭。**启用本身不读数据**，但读取真实历史必须在场授权。

1. 用户在场时，设置页点 `Enable Traceweave Provider`（或确认由我代点）。
2. 新建任务，目标包含 traceweave 关键词（例如 `traceweave history summary`）。
3. 启动任务 → 系统/应用内授权弹窗 → 用户点允许。
4. 读取摘要后记录**结构性统计**（字段是否齐全、样本量、时间范围），不保存个人内容。
5. 在任务页撤销授权，确认再次读取被拒。

## E3 独立审计（外部）

- 材料：[威胁模型](security_threat_model.md)、[同步设计](sync_protocol_design.md)、[发布检查单](release_checklist.md)。
- 需要：审计方、代码快照、披露窗口约定。当前没有审计方，里程碑保持进行中。

## F3 多机型矩阵（需要第二台设备）

- 至少一台不同厂商/系统版本的设备，跑核心回归（隔离用例 + 安装升级 + 档案恢复）。
- 产出差异清单；没有第二台设备前标记"受阻（设备）"。

## F4 自动同步（手动入口已交付，缺真实双设备闭环）

- 现状（2026-11-07）：正式应用已有配对对话框、设备管理与"同步现在"入口；自动同步默认关闭，
  打开后由前台触发 + `AutoSyncJobService` 周期任务执行。
- 已完成：手动入口、默认关闭的开关、周期任务、昨次结果展示。
- 仍未完成：**两台真实设备之间**的完整闭环（配对 → 同步 → 编辑 → 删除 → 断网恢复 → 重启 →
  撤销后拒绝重连），以及无人值守场景下的长期可达性。缺第二台设备时标记"受阻（设备）"。
