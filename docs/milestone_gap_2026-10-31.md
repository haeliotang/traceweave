# 里程碑现状与终极目标差距（2026-10-31）

本文件回答一个问题：**以“设备无关、用户主权、可迁移的个人计算底座”为终极目标，当前还缺什么。** 现状依据本仓库的里程碑表、六项优化收尾与设备收据；未验证的部分不写成已有能力。

## 1. 终极目标拆成可检验的四层

| 层 | 目标 | 判据 |
|---|---|---|
| L1 数据主权 | 记忆、任务、授权可导出、可校验、删除可传播 | 档案可恢复、墓碑优先、无云端依赖 |
| L2 设备无关 | 同一身份与数据可跨设备延续 | 两台真实设备完成配对、同步、冲突解决 |
| L3 本地智能 | 断网可用、输出可校验、模型可替换 | 端侧模型在设备上可评测且可回归 |
| L4 系统级落地 | 与系统 UI、权限、分发的整合 | 系统入口矩阵、更新通道、审计与合规 |

## 3. 缺口清单（按对终极目标的影响排序）

| # | 缺口 | 影响 | 现状证据 | 建议下一步 |
|---|---|---|---|---|
| 1 | **跨两台真机的同步未验证** | L2 的核心判据未成立 | 只有同机双安装；mDNS 跨设备未测 | 需要第二台设备；先跑配对再跑冲突/删除 |
| 2 | **正式包内没有同步入口的两端体验** | 用户无法真正用起来 | 同步 UI 只在源码与隔离包验证；正式包已打包库但无第二端 | 双端都在正式包后做一次端到端演练 |
| 3 | **模型输出曾受 128 token 原生上限** | L3 的文稿质量被截断 | 真实文稿 55 字节；**已重建运行时放开到 512 token / 2048 上下文**，目录预算 Qwen 256、MiniCPM 384 | 需用新上限重跑质量与 JSON 评测并出收据 |
| 4 | **无自动同步与后台调度** | 设备无关是手动的 | 自动同步仅前台尝试一次 | 设计草案已写：[auto_sync_design](auto_sync_design.md)；实现待做 |
| 5 | **无独立审计** | L4 的信任声明受限 | 威胁模型与范围已写，未审 | 外部审计方 |
| 6 | **无分发与更新通道** | 用户拿不到更新 | 侧载 + 开发密钥；商店未接 | 准备材料已写：[distribution_readiness](distribution_readiness_2026-10-31.md)；需要你决定签名归属与渠道 |
| 7 | **输入类弹窗仍为浅色；TalkBack 仅一次走查** | L4 的可用性 | 记忆/授权/导入/删除/配对等 7 个确认弹窗已深色；口令与云配置等含输入框的弹窗保持浅色；TalkBack 完成一轮主流程走查 | 输入类弹窗需要单独设计深色输入样式；TalkBack 需要多轮回归 |
| 8 | **系统级能力仍是实验** | 与 L4 的距离 | 悬浮窗、无障碍、传感器均标实验；通知/分享/文件选择已稳定 | 清点见 [system_capability_inventory](system_capability_inventory_2026-10-31.md)；建议先做零权限的静态快捷方式 |
| 9 | **Rust daemon 与 IPC 停用** | 长期架构未闭合 | 代码中 `run_tcp_server` 直接返回“disabled pending authenticated IPC” | 评估已写：[daemon_ipc_assessment](daemon_ipc_assessment_2026-10-31.md)；结论是短期不启用 |
| 10 | **无遥测、无崩溃上报** | 现场问题难复现 | 本地崩溃捕获已实现（`last_crash.txt`，随导出诊断携带）；**不自动上传**；方案见 [crash_reporting](crash_reporting_2026-10-31.md) | 自动上报需要用户同意与接收端，未做 |
| 11 | **功耗仍不足以支撑续航结论** | 续航结论缺失 | 2026-11-03 补了三次未插电窗口（143.7 / 95.7 / 227.4 mAh/h）：同样设定下两次「关」相差 2.4 倍，**10 分钟窗口无法分辨自动同步开关的影响** | 需要第二台设备与更长窗口（每段 ≥1 小时，A/B/A）或功率计；见 [power_measurement](power_measurement_2026-10-31.md) |

## 4. 已经不再缺的（避免重复投入）

- 严格 JSON 的“能不能输出合法结构”：GBNF 下 10/10；同模型无 grammar 对照为 1/10（差别主要来自 think 块占用预算），但内容正确性仍未解决；
- 配对是否需要手抄长串：SAS + 局域网发现 + 地址直连已替代；
- 同步库是否在正式包里：已在，且有发布校验；
- 主界面是否双语/紧凑：已迁移到 `T` 并有截图；
- 是否有审计可看：已只读展示并可导出 TSV。

## 5. 建议的下一阶段排序

1. **双真机同步演练**（缺口 1、2）：需要一台 Android 12+ 设备；
2. **放开模型 token 上限并重测**（缺口 3）：本地可做，先改原生常量再跑 50 题；
3. **弹窗深色与走查收尾**（缺口 7）：本地可做；
4. **分发与签名托管决策**（缺口 6）：需要用户决定；
5. **独立审计**（缺口 5）：需要外部方。

第 2、3 项不依赖外部条件，可立即继续。
